# history-writing-workflow（历史学写作工作流）

一套历史学论文写作的人机协作流程。

## 简介

这套流程的出发点是：AI 代写会削弱写作者本身的训练价值，但完全不用 AI 又浪费了它在检索、解释、评审上的能力。因此流程把写作拆成三个阶段，在每个阶段之间设置"闸门"——人必须亲自完成相应的思考、阅读或反馈，AI 才进入下一步。

两条基本原则：

1. 人始终在环中：选题评估、大纲评估设有 95 分的门槛，初稿每一段都需要人给出 50 字以上的具体意见，定稿以人确认完成为准。在此之前，AI 不推进流程。
2. AI 为问题服务，而非即时满足人的要求：AI 在流程中承担追问者、资料员、论敌、审稿人的角色，不代笔、不迎合。

## 流程概览

| 阶段 | 环节 | 进入下一环节的条件 |
|---|---|---|
| 一、问题的生成与文献的获取 | 1. 选题与要求（连环追问） | 思维评估 ≥95 分 |
| | 2. 核心文献获取（检索策略） | 人确认策略并完成检索 |
| | 3. 材料包打包 | 人确认材料包可用 |
| 二、文献精读与论文框架校正 | 4. 陪伴式精读 | 人声明完成精读 |
| | 5. 大纲双重校准 | 大纲评估 ≥95 分 |
| 三、初稿撰写、修改与定稿 | 6. 选定蓝本，提取论证模式说明书 | 人选定蓝本、完成说明书 |
| | 7. 分段撰写初稿 | 每段须人给出 ≥50 字意见 |
| | 8. AI 自评与人工事实核查 | 逐条核查完成 |
| | 9. 人工润色，审稿人循环评审 | 人确认定稿 |

## 使用方式

**方式一：让 Kimi 从仓库安装**

在 Kimi 对话框中发送：

```
从这个 GitHub 仓库安装技能：https://github.com/Kormont-Chiang/history-writing-workflow
```

**方式二：手动创建自定义技能**

1. 打开 `history-writing-workflow/SKILL.md`，复制全文；
2. 在 Kimi 输入 `/skill-creator`，将内容交给它，请它按此创建技能；
3. `references/` 目录下的四个文件一并提供。

**方式三：Kimi Code / 本地 Agent**

将 `history-writing-workflow/` 文件夹放入技能目录（如 `~/.kimi/skills/` 或 `~/.agents/skills/`），重启后生效。

## 目录结构

```
history-writing-workflow/
├── SKILL.md                              # 主文件：原则与各阶段闸门
└── references/
    ├── stage1-problem-literature.md      # 阶段一：选题追问、思维评估、检索策略、材料包
    ├── stage2-reading-outline.md         # 阶段二：精读支持、大纲校准
    ├── stage3-draft-finalize.md          # 阶段三：蓝本、分段写作、事实核查、审稿
    └── evaluation-rubrics.md             # 评分量表（选题、大纲、自评、审稿）
```

## 说明

- 流程以历史学论文为设计对象，其他学科的学术写作可参照调整。
- 使用中如有问题或建议，欢迎在 Issues 中提出。
